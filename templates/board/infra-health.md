# 环境健康（Infra Health）

> Owner: O1 运维官 · 每日由 routine R7 生成
> **共享云电脑是本项目最脆弱的环节。** 所有 Bot 共用一台机器，一个 Bot 装坏依赖，全队停工。

---

## 每日检查项

| # | 检查 | 命令 | 阈值 |
|---|---|---|---|
| 1 | 磁盘 | `df -h` | 剩余 > 20% |
| 2 | 僵尸车道 | `git worktree list` | 无超过 48 小时未活动的 worktree |
| 3 | 僵尸进程 | `ps aux \| grep -E 'node\|vite\|pnpm'` | 无孤儿 dev server |
| 4 | 端口占用 | `ss -tlnp` | 与 `locks.md` 的分段一致，无越段占用 |
| 5 | 过期锁 | 读 `board/locks.md` | 无持有超 1 小时的锁 |
| 6 | 依赖完整性 | `pnpm install --frozen-lockfile` | 退出码 0 |
| 7 | 冷启动可用 | `git clone` 到临时目录 + bootstrap + 跑一次测试 | 退出码 0 |
| 8 | CI 队列 | `gh run list --limit 10` | 无排队超 30 分钟 |
| 9 | staging | curl staging URL | 200 且构建号 = main 最新 |

**第 7 条是最重要的。** 它回答的是："一个新 Bot 今天加入，能不能在一次会话内跑起来？"
这个问题的答案一旦变成"不能"，团队扩张就会立刻卡死，且症状会伪装成"新 Bot 好笨"。

- 清理超过 48 小时未活动的 worktree（清理前把未提交内容打包到 `board/salvage/`）

- 强制回收超时锁并在 `locks.md` 记录

- 删除任何在 `git status` 中有未提交改动的车道

- 变更 CI 配置（那是 Q1 的车道）
