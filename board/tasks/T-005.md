# T-005 · Every command the SOPs print fails in a project

- Owner: @O1
- Reviewer: @human
- Milestone: S0
- Release condition it advances: S0 — "one project has run one task end to end under the
  framework". No agent has run anything yet, and the first one to take a lock or answer a
  stall alert would have got a file-not-found from a command this framework told it to type.

## 1. Goal

`node tools/lock.mjs`, `node tools/board/status.mjs`, `node tools/board/stall.mjs` and
`node tools/verify-protection.mjs` all work in a project, unchanged from how the SOPs,
routines and role cards print them.

## 4. Contracts

The mirror stays byte-for-byte identical to the upstream tag. That is the constraint that
rules out the obvious fix — rewriting the paths as they are mounted — and it is not being
relaxed.

## 5. Definition of done

- [ ] Four launchers are installed by the mount, each forwarding to its own path inside the
      mirror, each preserving arguments and exit code.
- [ ] A launcher naming a tool that is not mounted fails `gates.test.mjs`.
- [ ] No document prints two forms of the same command, and none tells an agent to work out
      a prefix for itself.
- [ ] `setup.md` step 9 runs the four commands before the positive end-to-end test.

## 6. Acceptance command

```bash
node tools/gates/gates.test.mjs
node tools/gates/selfcheck.mjs
node tools/gates/spec-check.mjs
```

## 7. Evidence

`evidence/T-005/` — command.txt, output.txt, diff-stat.txt, env.txt.

## 8. Timeout and escalation

- Expected: one session
- If blocked: escalate to @human.
- Three failed attempts: stop and write `board/blockers/T-005.md`. There is no fourth.
