# T-003 · Framework v3.0.1: the approval path the first real merge could not use

- Owner: @A1
- Reviewer: @human
- Milestone: S0
- Release condition it advances: S0 — "one project has run one task end to end under the
  framework". `sunset-club` T-000 got to the last step and stopped there, twice, for reasons
  the framework had documented incorrectly.

## 1. Goal

A reviewer following the written instructions can approve a pull request and have it merge.
Today they cannot: the instructions say to comment, and a comment triggers nothing.

## 2. Inputs

- `sunset-club` PR #2 — the merge this was found on
- `tools/gates/envelope-check.mjs` — reads approvals
- `tools/gates/lane-check.mjs` — prints `task=null` on board branches
- `tools/mount.mjs` — prints the wrong path on the last line of setup
- `docs/03-gates/gates.md`, `docs/04-grokbot/setup.md`,
  `docs/04-grokbot/skills/sop-task.md`, `docs/04-grokbot/skills/sop-review.md`,
  `docs/00-charter/constitution.md`

## 4. Contracts

None. The `APPROVED-BY` line and the gate that reads it are unchanged; only the instructions
for producing one, and three messages, change.

## 5. Definition of done

- [ ] Every document that names the approval mechanism says **review**, not comment.
- [ ] The gate's own failure message gives the command that works.
- [ ] Plain comments are still accepted, so an approval already in the timeline is not thrown
      away by this fix.
- [ ] A reviewer is told what to do when the newest run is green and GitHub still says blocked,
      and told not to use `--admin`.
- [ ] The lane gate does not print `task=null` on a branch that has no task by design.
- [ ] The path `mount.mjs` prints for the protection checker is the path it installs it to.

## 8. Timeout and escalation

- Expected: one session
- If blocked: escalate to @human. This card changes the rule the human is the last reviewer
  under, so there is nobody else to ask.
- Three failed attempts: stop and write `board/blockers/T-003.md`. There is no fourth.
