# 术语表 · 流程

> Owner: S1 典藏官
> **本表只收流程术语。** 游戏术语（角色属性、机制、经济）归各项目自己的术语表。
> 判据：这个词换一款游戏还用不用？用 → 这里；不用 → 项目仓库。

术语表存在的唯一目的是**消除猜测**。当文档里同时出现"车道"和"分区"，
新 Bot 会花时间猜它们是不是同一个东西，猜错就写错代码。

---

## 组织

| 术语 | 英文 | 定义 | 常见误用 |
|---|---|---|---|
| **工作室** | Studio | 制度层。跨项目、可复用的一切 | 说成"公司""团队" |
| **项目** | Project | 一款具体的游戏 | 说成"产品线" |
| **常委会** | Standing Committee | 跨领域裁决与规划的群聊，≤6 人 | 说成"全体会议" |
| **工段群** | Cell Group | 为某个任务临时组建的小群，用完解散 | 说成"小组" |
| **安灯群** | Andon Group | 拉安灯后临时组建的处置群 | |
| **岗位** | Role | 职责定义，工作室层 | 与"Bot 实例"混用 |
| **编制** | Staffing | 某个项目实际配了哪些岗位 | |

## 工作方式

| 术语 | 英文 | 定义 | 常见误用 |
|---|---|---|---|
| **车道** | Lane | 一个 Bot 独占的文件路径集合 + 它的 git worktree | 说成"分区""模块""目录" |
| **所有权表** | Ownership Table | 路径 glob → owner 的映射，G5 闸门的唯一依据 | 说成"权限表" |
| **越界** | Trespass | 修改了车道外的文件 | 说成"冲突" |
| **任务信封** | Task Envelope | 八段式任务卡 | 说成"工单""需求" |
| **证据包** | Evidence Pack | 真实执行输出的归档，`evidence/T-XXX/` | 说成"报告""截图" |
| **闸门** | Gate | 一道必须通过的检查，G1–G9 / H1–H2 | 说成"审核""检查点" |
| **契约** | Contract | 跨模块的数据结构定义，冻结后才可实现 | 说成"接口文档""协议" |
| **冻结** | Frozen | 契约进入不可改状态，改动需 ADR | 说成"定稿" |
| **心跳** | Heartbeat | 每 2 小时的状态更新 | 说成"日报""汇报" |
| **安灯** | Andon | 全线停工警报 | 说成"告警""事故" |
| **三振出局** | Three Strikes | 同一问题失败 3 次必须停手写阻塞报告 | 说成"重试上限" |
| **红队抽检** | Red Team Spot Check | 换人在干净环境重跑，对抗自证 | 说成"复查""抽查" |
| **规格漂移** | Drift | 代码与规格、或两份文档之间的矛盾 | 说成"不一致""bug" |
| **信任账本** | Trust Ledger | 记录谎报/越界/超时的表 | 说成"绩效""黑名单" |
| **缺陷逃逸** | Escape | 合入 main 之后才被发现的问题 | 说成"线上 bug" |

## 工作室层

| 术语 | 英文 | 定义 |
|---|---|---|
| **镜像** | Mirror | 项目仓库中 `docs/_studio/` 的只读框架副本 |
| **钉版本** | Pin | `.studio-version` 记录的框架 tag |
| **上升** | Elevation | 把项目层的东西搬到工作室层，受二次法则约束 |
| **下降** | Demotion | 把工作室层的东西退回项目层或删除 |
| **二次法则** | Rule of Two | 第二个项目真的需要之前，不许上升 |
| **能力账本** | Capability Ledger | 工作室会做什么了的清单，四级：未知/做过一次/已掌握/已产品化 |
| **启动成本** | Time to First Playable | 从立项到首个可玩切片的天数，工作室的核心指标 |
| **首次通过率** | First-Pass Yield | 一次过闸门无返工的 PR 占比 |

## 禁用词

以下说法在本工作室的文档中**不允许出现**，因为它们没有可判定的含义：

| 禁用 | 为什么 | 改成 |
|---|---|---|
| 「手感要好」 | 不可判定 | 帧数据表 |
| 「性能要好」 | 不可判定 | 具体预算数字 |
| 「进展顺利」 | 零信息量 | 完成了什么、剩下什么 |
| 「基本完成」 | 没有"基本"这个状态 | 状态机里的具体状态 |
| 「应该没问题」 | 猜测伪装成结论 | 跑了什么命令、退出码是多少 |
| 「稍后处理」 | 没有归属和时限 | 开一张任务卡 |
| 「临时方案」 | 临时方案会永久存在 | 写清回滚条件，或者别做 |
| 「我觉得」（用于数值） | 数值要有依据 | 遥测数据或模拟结果 |

> 最后一条对经济数值尤其重要：**没有遥测支撑的经济改动一律拒绝。**
