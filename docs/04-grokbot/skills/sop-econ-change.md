# SOP · 经济变更（Economy Change）

> 执行者：C1 经济官（提出）· T1 平衡官（复核）· Q1（G9 闸门）· 人类（重大变更批准）
> 规格：`docs/01-game/gdd-economy.md` · 模拟器：`packages/econ-sim/`
> **本 SOP 从 M5 起强制。M5 之前，任何经济数值都是占位符，不许当真。**

---

## 1. 为什么经济需要单独一套流程

战斗数值改错了，玩家当场就有反馈，改回来就行。

**经济数值改错了，三周后才会显现，而且改不回来。**

一个多产出 15% 的副本，第一周没人注意；第三周，市场上这类材料价格腰斩；第五周，所有靠制作这类物品谋生的玩家收入归零，他们不会发帖抱怨"材料掉率高了"，他们会直接不玩了。而此时你就算把掉率调回去，那些已经涌入市场的存量也回不去了。

能运营十年以上的网游，核心从来不是数值设计得多精妙，而是**它有一整套"投放-回收"的监控与调节机制，且改动极其谨慎**。

所以：**经济改动的默认答案是"不改"。** 这份 SOP 的大部分内容是在提高改动的门槛。

---

## 2. 什么算"经济变更"

以下任何一项，都必须走本 SOP：

| 类别 | 例子 |
|---|---|
| **投放** | 任何货币/材料的掉率、任务奖励、副本产出 |
| **回收** | 修理费、入场消耗、交易税、制作损耗、任何消耗品的消耗速率 |
| **时间锚资源** | 每日配额的上限、恢复速率、以及任何算法定价公式的参数。这类资源是整个经济的锚 |
| **转化** | 三种货币之间的兑换关系、声望的获取与用途 |
| **市场** | 交易行规则、手续费、挂单上限、价格区间限制 |
| **新增物品** | 任何可交易的新物品（它会占用现有物品的需求） |
| **新增产出点** | 任何新的赚钱途径 |

> **注意最后两条。** "加一个新装备"看起来是内容工作，但如果它可交易，它就是经济变更。
> 这是最容易漏掉的一类，也是最容易出事的一类。

## 3. 流程

```
1. C1 写变更提案 board/econ-proposals/EP-XXX.md
2. 跑基线模拟（不改动）与变更后模拟，各 ≥100 次蒙特卡洛，模拟周期 ≥ 90 游戏日
3. 对照 gdd-economy.md 的 8 条稳定性判据逐条检查
4. T1 独立复核：不看 C1 的结论，自己跑一遍，自己判
5. 任一判据不达标 → 拒绝，或修改提案重来
6. 全部达标 → 提 PR，附完整模拟报告
7. 重大变更（见 §5）额外需人类批准
8. 合入后，T1 建立为期 2 周的遥测观察，与模拟预测对比
```

### 第 4 步为什么必须是 T1 独立跑

因为 C1 会**无意识地调参数直到结果好看**。这不是舞弊，是所有做模拟的人都会犯的毛病：跑出不理想的结果，就想"是不是我某个假设设错了"，调一下，再跑，直到结果符合预期。

T1 拿到的只有提案里的**参数变更清单**，不看 C1 的模拟配置。它用自己的基线跑。两边结论不一致 → 说明有一方的假设有问题，必须先弄清楚，不许"取平均"。

## 4. 提案格式 `board/econ-proposals/EP-XXX.md`

```markdown
# EP-012 · 下调三层关卡金币产出 8%

## 1. 问题（用数据说话）
遥测显示三层关卡的金币时薪是二层的 2.3 倍，而难度只高约 40%。
过去 14 天，78% 的活跃玩家把 80% 以上的游戏时间花在三层。
→ 二层实质上已经死亡，这不是我们想要的分层结构。

## 2. 变更清单（精确到字段）
| 文件 | 字段 | 现值 | 新值 |
|---|---|---|---|
| content/levels/l3.json | gold_drop_mult | 1.00 | 0.92 |

## 3. 预期效果（可证伪）
- 三层时薪降至二层的 1.9 倍以内
- 二层的活跃玩家占比从 12% 回升到 20%+
- 金币总投放下降约 5.5%，通胀率回到目标带内

## 4. 八条判据模拟结果
| # | 判据 | 基线 | 变更后 | 达标 |
|---|---|---|---|---|
| 1 | 90 日通胀率在 [-3%, +5%] | +7.2% | +3.1% | ✅ |
| 2 | 基尼系数 < 0.62 | 0.58 | 0.57 | ✅ |
| 3 | 新手 7 日留存资产曲线为正 | ✅ | ✅ | ✅ |
| 4 | 无任何物品价格 90 日内变动 > 60% | ✅ | ✅ | ✅ |
| 5 | 算法定价公式收敛（不振荡） | ✅ | ✅ | ✅ |
| 6 | 服务型玩家收入 > 时薪中位数 0.8× | 0.71 | 0.85 | ✅ |
| 7 | 脚本收益率 < 人工收益率 0.6× | 0.44 | 0.42 | ✅ |
| 8 | 各层关卡时薪差距 < 2.0× | 2.3× | 1.88× | ✅ |

## 5. T1 独立复核
- 复核人：T1
- 是否看过 C1 的模拟配置：否
- 独立结论：判据 6 我算出 0.82（C1: 0.85），差异来自服务定价假设。
  差异不影响结论方向。**同意。**

## 6. 回滚条件（必填，可测量）
上线后 14 天内，若出现任一：
- 三层活跃占比未下降至 70% 以下
- 二层活跃占比未上升至 16% 以上
- 玩家整体日均在线时长下降 > 8%
→ 回滚至 1.00，并重新分析。

## 7. 沟通
本次变更需在版本公告中明示，说明理由。
★ 悄悄改数值是经济系统最忌讳的行为——玩家一定会发现，
   而"被瞒着"造成的信任损失，远大于数值本身的影响。
```

---

## 5. 需要人类批准的"重大变更"

| 条件 | 说明 |
|---|---|
| 影响货币总投放/回收 > 5% | 系统性影响 |
| 改动时间锚资源或算法定价的任何参数 | 这是整个经济的锚 |
| 新增任何产出货币的途径 | 加水龙头比加水槽危险得多 |
| 改动交易税或市场规则 | 影响所有玩家的行为模式 |
| 任一判据处于临界（达标但余量 < 10%） | 模型误差可能吃掉余量 |
| 上一次同类变更的回滚条件曾被触发 | 说明我们对这块的理解不够 |

---

## 6. 三条铁律

### 铁律一 · 先建监控，再动数值
没有遥测数据支撑的经济改动一律拒绝。**"我觉得这个掉率有点高"不是理由。**
如果连衡量它的数据都没有，那么改完之后也不会知道有没有变好。

### 铁律二 · 一次只改一件事
同一个 PR 里同时改掉率和修理费，出了问题无法归因。
两件事都要改 → 分两个 PR，间隔至少 7 天，中间观察遥测。

### 铁律三 · 加水槽优先于关水龙头
经济过热时，两种做法：减少产出（关水龙头）或增加消耗（加水槽）。

**优先加水槽。** 因为：
- 减少产出 = 直接削弱玩家已有的收入，体感是"被抢了"
- 增加消耗 = 提供新的花钱理由，体感是"有新东西"

同样是回收 100 万金币，"降低掉率 10%"会让玩家愤怒，"上线一个值得买的装饰品"会让玩家愉快。

这是长线运营网游最值得学的一条智慧，也是"服务型经济"这种设计的根本理由——**让玩家的钱流向其他玩家，而不是凭空消失。**
