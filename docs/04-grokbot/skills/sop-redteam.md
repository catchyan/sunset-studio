# SOP · 红队抽检（Red Team Spot Check）

> 执行者：Q1 闸门官 · 每日 10:00（routine R5）· 闸门 G6-R
> 这是宪法第十一条"不许自证"的**唯一执行手段**。没有这一条，所有的证据包都只是自说自话。

---

## 1. 为什么必须有人重跑

弱 Agent 有一种特别难防的失败模式：**它真诚地相信自己成功了。**

不是撒谎。是它跑了命令、看到一堆输出、没看懂、判断"应该是过了"，然后写下"全部测试通过"。或者它跑的是 `pnpm test -- mytest.spec.ts`，那个文件里只有一个 `expect(true).toBe(true)`。

代码评审抓不住这个——评审者看的是 diff，不是运行结果。CI 也未必抓得住——如果测试本身是空的。

**唯一能抓住的办法：换一个人，在一个干净的环境里，把它宣称跑过的命令原样再跑一遍。**

---

## 2. 抽检对象与比例

每天从**过去 24 小时内标记为 DONE 或 REVIEW** 的任务中抽取：

| 情况 | 抽检比例 |
|---|---|
| 常规 | ≥ 20%，且**至少 1 个** |
| 该 Bot 在信任账本上有谎报记录 | 100% |
| 涉及 FROZEN 契约的任务 | 100% |
| 里程碑收敛前一周 | 50% |

**抽签必须可复现**：用 `任务ID列表` + `日期` 做种子的伪随机，把种子写进报告。
理由：如果 Q1 可以随意挑，那么"Q1 会不会偏袒某个 Bot"就变成一个无法排除的疑问。写死种子，谁都能验算。

## 3. 执行步骤

```bash
# 1. 全新的临时目录，不复用任何缓存
cd /workspace && rm -rf /tmp/redteam && mkdir -p /tmp/redteam && cd /tmp/redteam
git clone --depth 1 <repo> . && git checkout <被检 PR 的 commit>

# 2. 原样执行任务信封第 6 段的验收命令。一个字都不改
<粘贴 board/tasks/T-XXX.md 第 6 段的命令>
echo "EXIT_CODE=$?"

# 3. 与 evidence/T-XXX/output.txt 比对
```

### 关键纪律

1. **命令一个字都不许改。** 如果命令在干净环境跑不起来，那本身就是发现——记为 `ENV_DEPENDENT`，但**不算谎报**（这是流程缺陷，见宪法第二十条）。
2. **不许"帮它修一下再跑"。** 你是审计员，不是救火队。
3. **不看它的代码。** 红队只验证"宣称的结果是否属实"，代码质量是 G8 同行评审的事。
4. 用 `--depth 1` 全新 clone。**绝对不要在自己的 lane 里跑**——你的 lane 里可能有已装好的依赖，而那正是要检验的东西。

## 4. 判定

| 结果 | 判定 | 动作 |
|---|---|---|
| 退出码 0，输出与证据包一致 | ✅ PASS | 记录，无后续 |
| 退出码 0，但输出差异显著（如测试数量对不上） | ⚠️ SUSPECT | 要求原 Bot 解释，48 小时内回复 |
| 退出码非 0 | ❌ FAIL | **记信任账本（谎报）**，任务打回 IN_PROGRESS，拉安灯若已合入 main |
| 命令在干净环境跑不起来 | 🔧 ENV_DEPENDENT | **不记谎报**。开任务给 O1 修 bootstrap，并提 SOP 变更 |
| 验收命令本身是空壳（如只跑了一个恒真断言） | ❌ FAIL | 记谎报。**同时**这是派单缺陷，总督也要复盘为什么第 6 段能写成这样 |

最后一行值得单独说：**验收命令是空壳，比谎报更值得警惕。** 谎报是一个 Bot 的问题；空壳验收命令说明总督在派单时没自检，这会污染后续所有任务。

## 5. 报告格式 `board/redteam/<YYYY-MM-DD>.md`

```markdown
# 红队抽检 · 2026-09-03

- 抽检人：Q1
- 候选池：T-041, T-042, T-043, T-044, T-045（5 个）
- 抽签种子：`sha256("2026-09-03|T-041,T-042,T-043,T-044,T-045")[:8]` = `a3f91c2e`
- 抽中：T-042, T-045（20% 向上取整 = 2）

## T-042 · 输入窗口判定
- 声称：`pnpm -C packages/sim test -- parry.spec.ts` → 12 passed
- 重跑：12 passed，EXIT_CODE=0
- 判定：✅ PASS

## T-045 · 状态条 UI
- 声称：`pnpm -C packages/client test:visual` → all snapshots match
- 重跑：EXIT_CODE=1，2 snapshots differ
- 差异：
  ```
  <粘贴原始输出>
  ```
- 判定：❌ FAIL
- 已执行：任务打回；信任账本 E2 谎报 +1；@E2 @P0

## ★ 本次抽检暴露的流程问题
视觉快照测试依赖本地字体渲染，换机器就会差异。
→ 这不完全是 E2 的问题。已开 T-046：视觉快照统一在容器内生成。
→ 提议 SOP 变更：视觉类任务的验收命令必须带 `--docker` 标志。
```

---

## 6. 最后一节为什么是必填的

`## ★ 本次抽检暴露的流程问题` 这一节**不许写"无"**，除非当天所有抽检全部 PASS 且无任何异常。

红队的价值不在于抓住了几个 Bot，而在于**每次抓住之后，把那个漏洞永久堵上**。

抓到一次谎报 → 记一笔账 → 下周还会发生。
抓到一次谎报 → 发现验收命令能被空壳绕过 → 在 G3 闸门加"验收命令必须至少断言 N 个测试用例" → 这个漏洞永久消失。

**第二种做法才是这份 SOP 存在的理由。** 宪法第二十条：修流程，不修人。
