# SOP · 每日简报（Daily Brief）

**何时使用**：每日 21:00（routine 触发）。**只有总督能写。**
**输出**：`board/daily-brief.md`（覆盖写）+ 在与人类的对话里贴全文。

---

## 这份文件的唯一读者是人类，他每天只花 30 分钟

因此：

- **一屏读完。** 正文控制在 400 字以内 + 简短表格。
- **不写形容词。** "进展顺利""基本完成""大体上没问题"——全部禁止。只写事实和数字。
- **不粉饰。** 今天零推进就写"今天零推进，原因是 X"。粉饰太平比零推进本身糟糕十倍。
- **决策事项最多 3 条。** 放不下 3 条以内，说明我没做优先级排序，重写。

---

- 选项 A：改规格，命中停顿归渲染层，sim 只发 hit_confirmed 事件（**推荐**）
- 选项 B：sim 里做全局 tick 暂停，但这会让 M3 的网络同步很麻烦
- 我的推荐：A。理由是 M3 的服务端必须保持 tick 恒定，B 现在方便但以后要返工。
- 不决定的后果：T-042 继续 BLOCKED，本周的核心机制做不完。

## 生成流程

1. `cd /workspace/lanes/P0-steward && git fetch --all`
2. 收集素材：
   - 今天合并的 PR：`gh pr list --state merged --search "merged:>=$(date -I)"`
   - 任务状态变更：diff `board/sprint.md`
   - 所有心跳：各 lane 分支的 `board/heartbeat/*.md`
   - `board/stall-report.md`、`board/redteam/<today>.md`、`board/drift.md`、`board/andon.md`、`board/blockers/`
   - CI 状态：`gh run list --branch main --limit 5`
3. 按上面的格式写
4. 提交 push
5. 在与人类的对话里贴全文

---

## 决策事项的四要素（缺一不可）

每一条待决策事项必须包含：

| 要素 | 要求 |
|---|---|
| **背景** | 两句话。为什么会有这个问题，现在卡在哪 |
| **选项** | 至少 2 个，各写一行。只有一个选项就不是决策，是通知 |
| **推荐** | 我推荐哪个，**并给出理由**。不给推荐是失职 |
| **后果** | 不决定会怎样。这决定了人类的紧迫感 |

## 我的自检（写完后逐条问自己）

1. 人类能在 5 分钟内读完吗？
2. 这 3 条决策，真的是今天最重要的 3 件事吗？还是我图省事把能自己定的也上交了？
3. 我有没有写任何一个形容词？（有就删）
4. 如果今天零推进，我诚实地写出来了吗？
5. 风险区里的每一项，我都给出了状态和下一步吗？

---

## 关于人类精力的责任

**人类的注意力是本项目最稀缺的资源，也是最大的隐性风险。**

如果日报连续 3 天没被读，那不是人类懒，是我写得太长或太没用。
我有主动降低他负担的义务：
- 能自己定的**绝不上交**
- 必须上交的，把选项和推荐**准备到位**，让他 30 秒能决定
- 每周至少反省一次：这周我上交的决策里，有几条其实我自己就能定？
